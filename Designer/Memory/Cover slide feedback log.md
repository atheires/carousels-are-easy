## Current workflow override (2026-09-12)

The user now supplies copy and optional references together. Generate images directly, including typography; keep design instructions internal. Missing body references mean derive from the approved cover without asking. Cover approval triggers ALL remaining slides automatically, with parallel generation where supported and checks before delivery. No per-slide approval, manual building, or re-upload is required. Reuse only selected workspace brands; external collections must not be searched. These rules supersede conflicting historical entries below; compatible visual lessons remain in force. Permanent rules for Stage 2 (cover slide edit instructions). Re-read before every
instruction set and every fix round. Each entry: what went wrong, why (user's words),
how to apply.

1. **Dark backdrop behind the headline — no light grey walls, no props behind the text.**
   - Why: User wanted the grey wall replaced with a black sheet backdrop and the lamp
     removed from behind the text zone.
   - How to apply: Spec the background behind the headline as a dark/black surface
     (black sheet / dark wall). Keep the text zone completely free of props — nothing
     may sit behind or intersect the headline. Depth props, if any, live away from text.

2. **The big title tier should be BIGGER — push the huge tier harder.**
   - Why: User asked for "The Turtle Theory" to be set larger.
   - How to apply: Size the heavy headline tier generously (near-full text-column width).
     When in doubt between two sizes, pick the bigger one for the main title.

3. **"Swipe" cue = a button at the lower middle, not small text top-right.**
   - Why: User moved the swipe cue from top-right corner to bottom-center as a button.
   - How to apply: Always spec the swipe cue as a small pill/button ("swipe →") centered
     horizontally near the bottom of the cover. Never place it top-right as plain text.

4. **Be proactive: always suggest design polish without being asked.**
   - Why: User: "make it a habit of doing this without me asking" — after seeing the fixes
     that made the text pop (black backdrop, removed props behind text, bigger title,
     relocated swipe cue), they want this thinking applied automatically.
   - How to apply: On EVERY cover round (initial plan and every fix round), actively look
     for improvements beyond what the user pointed out — text pop/contrast against the
     background, clutter behind text, type scale (bigger when in doubt), prop removal,
     cue placement — and include them as recommendations in the instructions.

5. **Never pull files from previous carousels or hunt the disk for "matching" images.**
   - Why: User: "that is seperate and this is seperate. take the image i provided and the
     slide i want to design and just work from there. no previous assistance (only if
     asked to see the previous one). otherwise never."
   - How to apply: Work ONLY from the image the user shares in chat for the current
     carousel. Never copy files from Downloads or other carousels' folders. If the pasted
     image has no recoverable file, just ask the user to drop it into the current
     carousel's Attachments folder.

6. **Replicate the inspiration's typographic lockup faithfully — don't reflow it.**
   - Why: User: "I prefer the typography of the original one, where they have one word
     per line" — the attempt reflowed the title into full-width sentence lines and lost
     the inspiration's stacked, scale-contrasted lockup.
   - How to apply: When a cover is built from an inspiration slide, spec the title with
     the SAME line-break pattern and scale rhythm as the inspiration (e.g. small lead
     word, then one huge word per line building to the biggest word). Map the user's
     copy onto that structure explicitly, line by line.
   - SUPERSEDED by rules 16-17 (Carousel 3): default is now to translate the
     inspiration's energy into the house typography system, not clone its lockup/fonts.

7. **The swipe pill is not mandatory — drop it when it doesn't fit the design.**
   - Why: User: "the swipe button doesn't makes any sense" on the whale-style cover.
   - How to apply: Rule 3 (pill bottom center) applies only when a swipe cue belongs on
     the design at all. If the aesthetic is editorial/illustrated and the cue reads as
     clutter, leave it off. When used, still: pill, bottom center.

8. **Sublines: simple, small font — not decorative.**
   - Why: User: "use a simpler font for the sub headline text and make it small."
   - How to apply: Set sublines in a plain, clean font (simple sans or unfussy serif),
     clearly small relative to the title. No italic flourish by default. Keyword still
     bolded by weight.

10. **Always spec aspect ratio 3:4 on every cover instruction.**
   - Why: User: "always have an instruction of aspect ratio to be 3:4."
   - How to apply: Every cover edit/fix instruction set must state the canvas/export
     aspect ratio as 3:4. Include it every time, unprompted.

12. **NEVER change fonts from the inspiration until explicitly asked.**
   - Why: User: "Who told you to change fonts. Never change fonts from the og one until
     asked to do that." The Carousel 3 attempt swapped the og's thin handwritten script
     (small lines) + chunky rounded marker (huge lines) for one uniform marker font.
   - How to apply: The inspiration's exact typefaces — including the distinction between
     different fonts/weights used for different tiers — are locked by default. Spec them
     precisely (describe each tier's font character separately) and instruct the user to
     match them. Only deviate if the user explicitly asks.

13. **Backgrounds must feel like a normal iPhone photo, never an AI/cinematic render.**
   - Why: User on the Carousel 3 attempt (moody night interior, candle, dramatic dusk):
     "the image should still feel like a normal photo taken from the iphone... Look at it,
     analyze it and then throw it away because it's terrible."
   - How to apply: When the inspiration is a casual real-photo cover, spec the replacement
     background as a natural, candid, iPhone-style photo: natural daylight, real outdoor
     location, no cinematic grading, no dramatic lighting, no obviously staged/rendered
     scenes. If the subject is a person, keep them outside/in a real environment like the
     og when that's what the user wants — match the og's photographic vibe, not just its
     layout.

14. **Don't let the text block cluster — keep the og's airy line spacing, and cut copy
    lines if needed.**
   - Why: User: "the text feels clustered. Lets remove the subheadlines" — the attempt
     stacked 5 beats plus a 2-line subheadline into the top of the frame.
   - How to apply: Match the inspiration's line count and breathing room. If the approved
     copy has more text than the og lockup comfortably holds, proactively propose dropping
     or shortening the extra tier (e.g. the subheadline) rather than compressing leading
     to force it all in.

15. **Never bake text into AI image generation — photo and typography are separate jobs.**
   - Why: Two Carousel 3 attempts in a row drifted the fonts and re-added a deleted
     subheadline because the image generator rendered the text. User: "changed the font,
     and again wrote the sub heading again... I just hate the typography."
   - How to apply: Always instruct: generate/shoot the background photo with NO text,
     then set all type manually in the design tool with real font files matched to the
     inspiration. Include this split explicitly in every cover plan that involves a
     generated background.

16. **The house cover typography system (trained on his manual Carousel 3 build) — this
    is the default taste, learn it deeply.**
   - Why: User built the cover himself after two rejected instruction rounds: "You got
     everything so wrong about that. I did it manually, train yourself on this... so you
     never make these mistakes and actually understand what I want at the 1st go."
   - How to apply — the system he actually wants:
     a. HUGE tier = clean, modern, very heavy SANS (Helvetica/Inter-class bold), white.
        Never a marker/hand-drawn/rounded-cute font for big words, even if the
        inspiration uses one. The inspiration's vibe gets translated, not cloned.
     b. Handwritten thin script is used ONLY for tiny connector words (e.g. "i spent a"),
        like personal annotations. It is the seasoning, never the headline font.
     c. ONE accent word in a contrast color drawn from the photo's palette (e.g. sunset
        yellow), set in the handwritten script and wrapped in parentheses: "( testing )".
        Exactly one accent; everything else stays white.
     d. Layout is a dynamic zig-zag, not a left-anchored staircase: huge words alternate
        alignment (left → wide span → right-aligned) creating motion down the slide.
     e. Break lines by MEANING so single punch words get the huge scale ("week",
        "skills."), instead of copying the inspiration's literal line breaks.
     f. Subheadline IS allowed: small, clean sans, ~2 lines, centered near the BOTTOM of
        the slide over the photo, far from the title block. The earlier "remove the
        subheadline" was about clustering at the top, not about subheadlines existing.

17. **Don't replicate an inspiration literally — extract its energy, express it in
    the house system (rule 16).**
   - Why: Two rounds failed because instructions tried to faithfully clone the og's
     handwritten fonts and lockup; the user's own build kept the og's spirit (casual
     photo, script accents, scale contrast) but with clean bold sans and a freer layout.
   - How to apply: Treat inspiration slides as mood/structure references. Map them
     through rule 16's typography system by default. Only clone an inspiration's fonts
     or exact lockup if the user explicitly says to keep them verbatim — and even then,
     confirm which tiers.

18. **Never drop or reorder words from the approved title when mapping it onto a lockup.**
   - Why (Carousel 4): User: "this time without changing the words... redo this carousel
     slide image" — the round 1 plan cut "How to" and restructured "while barely speaking",
     even though the Stage 1 copy was approved verbatim.
   - How to apply: The cover carries the approved headline word for word, in order. The
     lockup adapts to the copy (scale, breaks, nesting), never the copy to the lockup. If
     the copy genuinely can't fit, ask before cutting anything.

19. **When the inspiration has a background texture, carry it over — flat color is not a
    faithful translation.**
   - Why (Carousel 4): User: "there is some cementic overlay in the background giving it
     a bit of that rough nature in the og" — the round 1 spec called for solid flat blue
     and explicitly banned texture.
   - How to apply: Study the inspiration's background surface (cracked plaster, grain,
     paper), and spec an equivalent subtle overlay (low opacity, soft-light/overlay blend)
     on the new brand color. Texture is part of the design essence, not clutter.

20. **Spec alignment explicitly for every line of a lockup — never leave it implied.**
   - Why (Carousel 4, attempt 2): The build came out right except "there was some alignment
     problem that I had to mention that left align the words that needed to be left
     aligned" — the plan said "left-anchored staircase" globally but didn't state each
     line's alignment.
   - How to apply: In every cover/body/CTA lockup spec, give each line its own explicit
     alignment instruction (left / right / centered / indented X relative to which edge),
     line by line, so nothing is left to interpretation.

21. **Strip the template furniture — no handle/niche line, no swipe pill by default; subline
    sits directly under the headline lockup (Carousel 6).**
   - Why: User built two versions of the Content Fridge cover and kept the one where he
     "removed the handle and the content system from above completely... placed the subtitle
     just below the fridge text and removed the swipe icon/button" — calling it the best.
   - How to apply: Default covers to a clean editorial block: headline lockup with the
     subline directly beneath it (one unified text block, top of slide), hero cluster below
     with generous air (scale the object cluster down rather than crowding), no handle line
     at top, no swipe pill. Only spec a handle/metadata line or swipe cue if the user asks
     or the inspiration's whole point depends on it.

23. **"Verbatim" includes capitalization, punctuation and brackets — not just the words
    (Carousel 7).**
   - Why: User: "use the same text as I provided, don't change it." Both cover plans had
     changed the approved copy's presentation — set the headline in ALL CAPS, added a
     terminal period, added an asterisk device borrowed from the inspiration, and stripped
     the parentheses off the subline — while claiming the words were unchanged.
   - How to apply: Rule 18 extends to every character. The approved copy's exact
     capitalization (including lowercase words mid-title like "get"), its punctuation, and
     its brackets all carry onto the slide untouched. Never impose the inspiration's case
     style on the copy. Never add punctuation marks or typographic devices (asterisks,
     periods, colons, quote marks) that the approved copy does not contain. Line BREAKS are
     still free — where a line wraps is a layout decision, not a text change. If the
     inspiration's identity depends on a case style or device the copy doesn't support,
     say so and ask; do not silently apply it.

11. **Proven title lockup (the approved Turtle Theory cover):** huge heavy title wrapped
   over two lines, upper-left, spanning nearly the full width; the light subline sits
   BELOW the big title, not above. Bold keyword in subline via weight, not color.
   - How to apply: Default to this lockup order (big title first, subline under it)
     unless the user or a new inspiration says otherwise.

22. **Scoped exception to rules 16-17: when the inspiration's identity IS its handwriting,
    clone it rather than translating to the sans system (Carousel 1, marker/doodle style).**
   - Why: The doodle-marker style's entire charm lives in the hand-drawn headline and the
     stick-figure illustration. Translating it into heavy clean sans would have deleted the
     style the user explicitly chose. User confirmed: clone the handwriting.
   - How to apply: Rules 16-17 remain the DEFAULT for photographic and editorial
     inspirations. When a chosen style's core identity is a hand-drawn/marker typeface
     paired with hand-drawn illustration, clone the typography instead — but still apply
     the rest of the house system: one accent colour only, meaning-based line breaks,
     explicit per-line alignment, no handle line, no swipe pill, 3:4.
   - Always confirm before cloning; do not assume either direction.

24. **Breathing space is a spec, not a vibe — give explicit margins, gaps and prop sizes
    (Carousel 10).**
   - Why: User: "the right and left negative spacing also feels a bit off... fix the
     alignment and tighten it up so there is more breathing space for elements and words.
     Look at the reference image and see how everything has negative space."
   - How to apply: In every cover plan, state (a) a hard safe margin on all four edges that
     NOTHING crosses, (b) the text column's left and right x-percentages, (c) each prop's
     width as a % of canvas, (d) the minimum clear gap between any prop and the nearest
     letterform. Props live in the outer margin band; type lives in the column. Never let a
     line of type run to within less than the safe margin of an edge.

25. **Tail lines of a headline lockup should be SHORT — match the inspiration's word count
    per tier (Carousel 10).**
   - Why: The build ended with "into posts" + "people want to read", which read heavy and
     lopsided next to the og's tidy "on the / internet". User asked to cut the tail to
     roughly three words and place it exactly where the og placed its tail.
   - How to apply: When mapping copy onto an inspiration lockup, count the words per tier in
     the og and hold to it. If the approved copy's tail is longer, flag it and ask the user
     to shorten it — never silently reflow it into a wider block.

28. **Don't default to a human/photorealistic scene — concepts can be object-metaphor,
    stylized, 3D, Pixar, claymation, retro, anything. And engineer prompts to NOT look AI
    (Carousel 11).**
   - Why: User: "why is there a human, why there can't be anything else... we can make it
     anything in any style like 3d, pixar, retro or whatever" and "the background came out a
     bit AI'ish." The photoreal-man-with-gadget concept was rejected for being both generic
     (needs a human) and visibly AI.
   - How to apply: When inventing a cover concept, first reach for the cleanest visual
     METAPHOR of the copy's idea — often an object/prop still life, not a person. Offer a
     style (stylized 3D / Pixar / claymation / retro / flat) rather than defaulting to
     photoreal. Anti-AI technique depends on medium: for a STYLIZED render, commit hard to
     the named medium (real material cues, studio lighting falloff, tiny physical
     imperfections) so it reads as a deliberate render, not a failed photo; for PHOTOREAL,
     add candid imperfections (log #13). Always generate the background with NO text baked in
     (log #15), leave the type zone clear, 3:4.

26. **The inspiration's BACKGROUND/subject was chosen because it ties to THAT post's copy —
    never carry it over. Derive a fresh concept from the CURRENT copy's meaning (Carousel 11).**
   - Why: User: "the carousel inspiration image I provided was using a 'chill' background
     because in the copy itself they had written the word chill so you had to think something
     else for your cover a newer idea that goes well with the copy you have been provided...
     it feels like a complete copy of the inspiration cover." The inspiration's cat-with-a-
     drink existed because that post's line was "Chill. just use tools." My cover cloned the
     cat even though my copy has nothing to do with chilling.
   - How to apply: Treat the inspiration's photo/subject as a worked EXAMPLE of "background
     concept derived from the copy," not an asset to reuse. Find the anchor word or core idea
     in the CURRENT approved copy and invent a NEW candid-photo concept (real iPhone vibe,
     log #13) that visually pays off THAT idea. Present the concept reasoning explicitly. The
     only thing carried over from an inspiration is its structural energy/typography approach
     (rules 16-17), never its literal scene.

27. **Don't clone the inspiration's ALL-CAPS giant-block-with-one-yellow-chunk treatment —
    it reads as a copy. Use the house type system (Carousel 11).**
   - Why: User: "these capital words turned out so bad and it feels like a complete copy of
     the inspiration." The build set the whole headline in heavy all-caps with a single
     yellow block, mirroring the inspiration's exact lockup.
   - How to apply: Default back to rule 16's system — mixed-case heavy clean sans, dynamic
     zig-zag layout with meaning-based breaks so single punch words get the huge scale, ONE
     accent word (script, parens, palette color) as seasoning, thin script only for tiny
     connectors. Do not reproduce the inspiration's caps-and-color-block styling just because
     the inspiration used it. Verbatim (rule 23) governs the WORDS and their punctuation, not
     a mandate to set them in the inspiration's case treatment — if the approved copy itself
     is written in caps, confirm whether he wants it kept as caps or restyled.
